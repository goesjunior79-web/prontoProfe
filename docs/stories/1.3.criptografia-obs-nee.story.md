## Goal

Criptografar campo `obs_nee` (laudos médicos) em repouso usando AES-256-GCM
com chave derivada por usuário. LGPD compliance — dado sensível protegido
mesmo se o banco for comprometido.

## Acceptance Criteria

- [x] `lib/db/encryption.js` exporta `encrypt`, `decrypt`, `tryDecrypt`, `looksEncrypted`
- [x] AES-256-GCM (autenticated encryption)
- [x] Chave derivada via HKDF-SHA256 com info `sesi-edu:user:{userId}` (chave única por professora)
- [x] IV de 12 bytes random a cada encrypt
- [x] Tag de 16 bytes detecta tampering
- [x] Token formato `v1.{iv}.{tag}.{ciphertext}` (base64)
- [x] Validação master secret (`SUPABASE_ENCRYPTION_SECRET` ≥ 32 chars)
- [x] `lib/db/alunos.js` integra: encrypt no INSERT/UPDATE, decrypt no SELECT
- [x] `tryDecrypt` para listagens (não quebra se 1 row corrompida)
- [x] Testes (23 novos) cobrindo round-trip, tampering, chaves diferentes, edge cases
- [x] `npm test` passa (220/220)

## Como funciona

```
[Professora cadastra aluno com obs_nee="TDAH"]
  ↓
[POST /api/alunos]
  ↓
[createAluno({ userId, obs_nee: 'TDAH', ... })]
  ↓
[encrypt('TDAH', userId)]
  ├─ deriveKey(MASTER_SECRET, userId) → key (256 bits)
  ├─ iv = randomBytes(12)
  ├─ AES-256-GCM(plaintext, key, iv) → ciphertext + tag
  └─ retorna 'v1.{iv}.{tag}.{ciphertext}'
  ↓
[INSERT INTO alunos { obs_nee: 'v1.AbCd...', ... }]
  ↓
[Banco armazena ciphertext]

[Listagem]
  ↓
[SELECT obs_nee FROM alunos]
  ↓
[tryDecrypt('v1.AbCd...', userId)]
  ├─ deriveKey(MASTER_SECRET, userId) → mesma key (HKDF determinístico)
  ├─ AES-256-GCM-Decrypt → 'TDAH'
  └─ retorna plaintext
  ↓
[App mostra 'TDAH' pra professora]
```

## Segurança

| Propriedade | Implementação |
|---|---|
| **Confidencialidade** | AES-256-GCM em repouso |
| **Autenticidade** | GCM tag detecta tampering |
| **Multi-tenancy** | Chave derivada por `userId` — professora B não consegue ler dados de A |
| **Rotação** | `VERSION = 'v1'` no token permite migração futura (v2 algorithm) |
| **Master secret** | `SUPABASE_ENCRYPTION_SECRET` em env var (nunca commit) |
| **HKDF** | Standard NIST para derivação de chave |
| **IV único** | Random 96 bits por encrypt → criptografias diferentes mesmo plaintext |

## Variável de ambiente nova

```bash
SUPABASE_ENCRYPTION_SECRET=<gerar com: openssl rand -base64 32>
```

⚠ **Crítico:** se essa secret for **perdida**, todos os obs_nee criptografados
ficam ilegíveis. **Backup é mandatório.**

## Falhas defensivas

- `decrypt` joga erro em token inválido → endpoints retornam 500 ou usam `tryDecrypt`
- `tryDecrypt` retorna fallback (null default) + loga warning → não quebra listagens
- Listagens com 1 row corrompida continuam funcionando (resto vem ok)
