## Pipeline em ASCII

```
[Cliente]
  │
  ▼
[runPipeline()]
  │
  ├─► [Generator: PROMPT MESTRE + cache] ─► v1
  │       │
  │       ▼
  │   [Validator determinístico em v1]
  │       │
  │       ├─ structural error? → continue (skip critic, regenera)
  │       └─ ok →
  │       │
  │       ▼
  │   [Critic: PROMPT 6 v2 + cache] ─► v2
  │       │
  │       ▼
  │   [Validator determinístico em v2]
  │       │
  │       ├─ ok →  ✅ retorna { content: v2, passed: true, attempts, usage, custo }
  │       └─ falha → continue (max 3)
  │
  ▼
Após 3 tentativas: retorna lastV2 com warnings
```

## Comportamento detalhado

### Skip critic em erro estrutural
Se v1 tem erro estrutural (`STRUCTURE_MISSING_SECTION`, `MISSING_SIGNATURE`, etc),
não chama o critic — vai direto pra próxima tentativa. Economiza ~50% dos tokens
em retries.

Erros que disparam regeneração imediata:
- STRUCTURE_MISSING_SECTION
- STRUCTURE_OUT_OF_ORDER
- STRUCTURE_MISSING_LEVEL
- MISSING_INTERACTIVE_QUESTION
- MISSING_SIGNATURE
- MISSING_CARTAO_RESPOSTA

Erros que vão pro critic (ele consegue corrigir):
- FORBIDDEN_TERM
- (warnings em geral)
