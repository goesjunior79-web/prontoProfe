## Parser de horário semanal

Aceita várias formas:

| Entrada | Saída |
|---|---|
| `seg 2, ter 2, qua 2, sex 1` | 4 dias / 7 aulas |
| `segunda 3, terça-feira 1` | 2 dias |
| `SEG 2, Ter 1` | case-insensitive |
| `seg:2, ter:1` | 2 dias |
| `seg 1; ter 2` | aceita ; |
| `seg 1, seg 2` | soma duplicatas (1 dia, 3 aulas) |
| `xyz abc` | erro: nenhum dia reconhecido |

Saída sempre **ordenada por dia da semana** (segunda → sábado).

## Como funciona

```
[Usuária acessa /aula]
   (opcionalmente vindo de /ptd com query params)
  ↓
[Form: Ano + Componente + Capítulo + Horário semanal]
  ↓ (background)
[GET /api/planejamentos?tipo=PTD&ano=...&componente=...&capitulo=...&limit=1]
  ↓
[Se encontrar: banner verde "PTD ativo" + snippet vai pro prompt]
  ↓
[Parser valida horário semanal em tempo real]
  ↓
[Botão "Gerar semanário"]
  ↓
[POST /api/generate { tipo_de_saida: 'aula' }]
  ↓
[runPipeline com PROMPT MESTRE]
  ↓
[Tela mostra:
   - Tabs por dia da semana
   - Output filtrado por tab (heurística split)
   - Tab "Tudo" mostra texto inteiro
   - Botão "Copiar tudo"]
  ↓
[POST /api/planejamentos (salva tipo='aula')]
```

## Heurística de split por dia

Output do LLM organizado em tabs via regex que detecta cabeçalhos de dia:
- "SEGUNDA-FEIRA", "Segunda", "SEG", etc (case-insensitive)
- "TERÇA-FEIRA", "Terca", "TER", etc
- ...

Se LLM não usar cabeçalhos consistentes, tab "Tudo" sempre mostra texto
completo (fallback seguro).
