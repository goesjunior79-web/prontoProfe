## Goal

Substituir `SESI_SYSTEM_PROMPT` (genérico, ~10 linhas) em `pages/api/generate.js`
pelo PROMPT MESTRE consolidado (~165 linhas) com versionamento e Anthropic Prompt
Caching ativo. Aceitar `tipo_de_saida` no request body com validação não-bloqueante.

## Context

Pré-requisito da FASE 0 (Bedrock). Sem PROMPT MESTRE em produção, todas as
gerações continuam usando system prompt genérico que não inclui:
- 4 regras absolutas (No Invention, etc)
- Princípio guia "praticidade da professora"
- Semântica contextual N1-N4
- Regras éticas de Observação/Relatório
- Termos proibidos
- Estruturas obrigatórias por módulo
- 4 critérios de validação final

Sem isso, US-002 (Validador), US-003 (Pipeline G+C), US-005..US-011 (Telas)
ficam sem base.

## Notes

- **Backward compatibility:** chamadas existentes (sem `tipo_de_saida`) continuam
  funcionando. O LLM infere o tipo do prompt textual + meta.tipo.
- **Anthropic Prompt Caching:** primeira chamada paga full input cost; subsequentes
  em até 5min pagam ~10% (TTL 5min). Pra apps com uso esporádico, considerar
  estratégia de keep-alive futuramente.
- **`provider` legacy:** request body antigo aceitava `provider` (já removido em
  commit `bcf1bb9`). Agora ignorado silenciosamente — sem warning.
- **Temperatura 0.3:** mais determinístico que default 1.0. Reduz "criatividade"
  do LLM, alinha com regra "No Invention".

## Riscos endereçados

| Risco | Mitigação |
|---|---|
| Quebrar fluxo atual | `tipo_de_saida` opcional, fallback razoável |
| Cache TTL 5min reduz hit rate | Será monitorado em US-016 (Cache strategy) |
| Aumento de tokens consumidos | Caching reduz ~90% após 1ª chamada |
