## Endpoints prontos

```
GET    /api/alunos                  → lista alunos da professora
GET    /api/alunos?turma=A&serie=3º → filtros
POST   /api/alunos                  → cria (com consentido=true)
GET    /api/alunos/:id              → busca + audit VIEW
PATCH  /api/alunos/:id              → atualiza nome/turma/serie/obs_nee
DELETE /api/alunos/:id              → soft delete (deleted_at = NOW())
```

Todos requerem `session.user.id` (UUID Supabase via NextAuth — US-004a).
Todos disparam `logAcesso` automático.

## Audit log LGPD

Cada operação grava em `acessos_dados`:
```js
{
  user_id: 'uuid-prof',
  aluno_id: 'uuid-aluno',
  acao: 'CREATE' | 'VIEW' | 'UPDATE' | 'DELETE' | 'EXPORT',
  recurso: 'alunos',
  metadata: { turma, serie, campos: [...] },
  created_at: NOW()
}
```

Falha no audit log **não bloqueia** a operação principal — só loga warning.

## Migração `localStorage` → Supabase

Função `migrateLocalToSupabase` é idempotente (flag `sesi_alunos_migrated`).
Funciona client-side, chama POST /api/alunos pra cada aluno.

Chamada sugerida (a ser implementada na UI em US-013):

```js
import { migrateLocalToSupabase, hasAlreadyMigrated } from '@/lib/db/migrate-local';

useEffect(() => {
  if (session?.user?.id && !hasAlreadyMigrated()) {
    migrateLocalToSupabase().then(({ migrated, errors }) => {
      if (migrated > 0) toast.success(`${migrated} alunos migrados`);
      if (errors.length) console.warn('Erros migração:', errors);
    });
  }
}, [session]);
```
